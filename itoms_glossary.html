ITOMS Master Glossary & Object Library

Purpose: Canonical language and object reference for ITOMS. Every first-class object has a permanent Object ID, exactly one Primary Domain, a stable Domain Tag, lifecycle policy, relationships, and schema mapping.

Repository rule: Read REPO_START_HERE.md before changing terminology, schema, UI, workflows, or architecture. Names are labels. IDs are identity.

Canonical IDs, Domains, Domain Tags, and Facets

Object ID: Permanent concept identity such as OBJ-AST-0001. Runtime tenant records have separate instance IDs such as AssetID.

Primary Domain: Every first-class object has exactly one authoritative PrimaryDomainID. DomainTag is the stable readable label such as INV, ORG, or GRC.

Facet: A lens such as HR, IT, Finance, Security, DR, Executive, Business Manager, or Inventory Control. Facets do not change canonical ownership.

DNS terminology: Internet Domain OBJ-IDN-0001 is the canonical technical Asset when a DNS namespace requires independent identity or history. Company may use PrimaryInternetDomainID plus the convenience label PrimaryInternetDomain; neither is architectural PrimaryDomainID.

Local Agent Platform Terms

TermArchitectural meaning
ITOMS Local Agent PlatformCross-platform endpoint architecture providing trusted identity, observation, bounded local history, disconnected operation, controlled execution, recovery, and user support.
Device AgentMachine-facing privileged endpoint service associated with canonical Device OBJ-DEV-0001; it is not a duplicate Device or unrestricted remote shell.
Support AppSeparate person-facing endpoint application that requests support, presents approved local status, and communicates with the Device Agent through authenticated, capability-scoped local IPC.
Authorized jobAuthenticated, tenant- and Device-scoped, expiring, replay-resistant request for a capability permitted by platform and local policy. Technical completion does not automatically complete business work.
Store-and-forwardBounded continuation of permitted local observation and queued delivery while ITOMS is unreachable, preserving capture time, delivery time, ordering, expiry, and collection gaps.
Agent ManagedCandidate management classification for a Device intentionally enrolled in the ITOMS Device Agent. Discovery, ownership, and OEM licensing remain separate concerns.

Agent Installation, Job, Command, Collector, and Support App are architectural or operational concepts, not new canonical first-class objects under ADR-0009.

IT Atlas and Canonical Ontology v1

Atlas publishes reusable reference knowledge. ITOMS owns tenant context, implementation, Evidence, decisions and history. Content Driver Case reuses OBJ-CAS-0001; Source reuses OBJ-EVD-0001; Context Statement reuses OBJ-OBS-0001. Authority is a party role. Applicability, adoption, decision and exception are versioned relationship/result records.

Guidance, Objective, Implementation Option and Compliance Driver are proposed canonical extensions in the same registries. See Canonical Ontology v1 and Atlas integration contract.
